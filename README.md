##Питання для самоконтролю
1. **Що таке система керування версіями? Які її переваги?**  
   Система керування версіями — це програмне забезпечення для фіксації та відстеження змін у файлах проєкту з часом. Вона дозволяє повертатися до попередніх версій коду, безпечно розробляти нові функції.

2. **Чим відрізняється локальний репозиторій від віддаленого?**  
   Локальний репозиторій розміщений на комп'ютері розробника, а віддалений — на сервері в мережі (наприклад, GitHub).

3. **Для чого використовуються команди Git?**  
   - `git init` — створення нового репозиторію.  
   - `git add` — він має відстежувати зміни, внесені до певного файлу.  
   - `git commit` — збереження змін в історії.  
   - `git status` — перевірка стану файлів.  
   - `git log` — перегляд історії комітів.

4. **Що таке гілка у Git? Для чого вона використовується?**  
   Це паралельна лінія розробки, яка дозволяє працювати над новими функціями без ризику пошкодити основний код.

5. **Як виконати злиття гілок? Що таке конфлікт злиття?**  
   Злиття виконується командою `git merge`. Конфлікт виникає, коли в одних і тих самих рядках збережено різні зміни; вирішується вручну вибором потрібного коду.

6. **Які кроки потрібно зробити, щоб підключити локальний репозиторій до GitHub чи GitLab?**  
   Створити віддалений репозиторій ➔ використати `git remote add origin <URL>` ➔ відправити код командою `git push`.

7. **Чим відрізняються git push і git pull?**  
   `git push` відправляє зміни з комп'ютера на сервер, а `git pull` завантажує зміни із сервера на комп'ютер.

8. **Що таке fork і pull request? Де вони застосовуються?**  
   *Fork* — створення особистої копії чужого репозиторію. *Pull Request* — пропозиція внести свої зміни до основного проєкту. Застосовуються для спільної розробки програмного забезпечення та внесення змін до чужих або командних репозиторіїв на платформах на кшталт GitHub, GitLab

9. **Які правила варто дотримуватися при написанні повідомлень до коммітів? **  
   Повідомлення мають бути короткими, зрозумілими, описувати конкретну зміну та виконуватися в єдиному стилі.

10. **Чому Git є розподіленою системою контролю версій? **  
    Тому що кожен розробник має повну копію всього репозиторію з усією історією змін локально на своєму ПК.
